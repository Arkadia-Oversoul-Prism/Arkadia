# EXP-002 · Raw Audio → Musical Object

**Status:** DEVICE VERIFICATION REQUIRED  
**Date:** 2026-10-02

## Question

Can the native mobile capture become an inspectable musical object without a cloud model?

## Input protocol

1. Hold **Hold to capture**.
2. Hum one sustained note for 2–5 seconds.
3. Release.
4. Wait for interpretation.
5. Play **PLAY ORIGINAL**.
6. Inspect the object type, confidence, detected pitch, and JSON.

## Current implementation

- 16 kHz mono PCM capture.
- WAV source preservation.
- deterministic autocorrelation pitch candidate.
- RMS energy.
- zero-crossing rate.
- provisional classification:
  - `melody_candidate`
  - `rhythm_or_percussive_candidate`
  - `ambiguous`
- confidence is explicitly provisional.
- source path and parent provenance are represented in the object.

## Evidence required

Record:

`CAPTURE_TIME`  
`DURATION`  
`INPUT`  
`EXPECTED_INTENTION`  
`INTERPRETATION`  
`PITCH`  
`CONFIDENCE`  
`PLAYBACK`  
`OBJECT_JSON`  
`FAILURE`  
`RECOVERY`

## Falsifier

If a simple sustained hum repeatedly produces unstable or misleading pitch candidates on the target Android device, do not paper over the result. Record the failure and revise the interpretation hypothesis.

## Status rule

No PASS until the APK is built and the flow is exercised on a real device.
