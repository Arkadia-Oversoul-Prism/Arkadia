# CP-10.5 — MECHANISM CANDIDATE: HYBRID ORIGIN EVIDENCE

**Status:** candidate / mechanism-bearing / falsifiable / not eligible / not selected / not implemented

## Constitutional question
Can a mechanism establish that a defined subject deliberately originated a specific authority event across CP-10.4's five dimensions without making the mechanism, identity layer, PassSpec, authorization state, or execution state the source of sovereignty?

## Candidate chain
`SUBJECT → DELIBERATE ACT + EVENT CONTEXT → SPECIFIC AUTHORITY EVENT → ORIGIN EVIDENCE SET → PROVENANCE → AUTHORIZATION → PASSSPEC (governed scope) → K15 → K3`

The intended inversion is:
`PassSpec → Human Authorization` (current collision)  →  `Subject/Event/Origin Evidence → Provenance → Authorization → PassSpec scope`.

## Evidence composition
The candidate proposed a hybrid evidence architecture combining subject/session evidence, event-specific interaction, event binding, temporal/contextual evidence, structural integrity, and deliberate-origin evidence. No component was granted automatic origin status.

## Arena obligations
D3 must distinguish `SUBJECT → ORIGINATED → EVENT` from association, participation, observation, delegation, inheritance, automation, derivation, replay, and execution.

D4 must distinguish deliberate origination from ordinary interaction, automated consequence, delegation, replay, inheritance, and unintended interaction.

## Result
The candidate was conceptually coherent but mechanism-sufficient evidence was not demonstrated. D3 origin relation remained UNKNOWN, D4 remained UNKNOWN, and eligibility was not established. The repository's PassSpec→human-authorization collision remained live.

The candidate therefore remained unselected and unimplemented.
