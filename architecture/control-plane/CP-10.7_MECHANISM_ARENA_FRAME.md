# CP-10.7 — MECHANISM ARENA EVALUATION FRAME

**Status:** arena frame / schema-only / normative / technology-neutral

## Constitutional question
How must a mechanism candidate demonstrate positive D3/D4 origin relations without allowing the mechanism, identity layer, PassSpec, authorization state, or execution state to become sovereignty?

## Candidate submission contract
M1 mechanism claim  
M2 positive instantiation  
M3 false-positive distinction  
M4 boundary preservation  
M5 failure semantics

## Evidence states
`E1 Evidence Presence` → evidence exists  
`E2 Evidence Discrimination` → evidence differentiates the target from false positives  
`E3 Evidence Sufficiency` → required dimensions satisfied with no forbidden substitution or contradiction.

No collapse:
`EVIDENCE EXISTS ≠ EVIDENCE DISCRIMINATES ≠ EVIDENCE IS SUFFICIENT ≠ PROVENANCE ≠ AUTHORIZATION ≠ EXECUTION`

## Central counterfactual test
Compare a target world in which the subject originated the authority event with a counterfactual world in which the same subject is merely associated with an already-existing event. A candidate must demonstrate an observable difference attributable to origination, not merely assert that one exists.

## False-positive arena
D3: association, session ownership, interaction, automation, delegation, derived event, witness, successful execution.  
D4: unrelated deliberate interaction, authentication-triggered automation, deliberate A causing derived B, delegation, replay, ambiguous interaction.

## Anti-laundering
L01 approved=true→origin=true; L02 PassSpec wrapper; L03 duplicated assertions; L04 downstream authorization→upstream provenance; L05 accumulation of weak associations; L06 execution→proof of origin.

## Flow
`CANDIDATE → ARENA → ELIGIBLE / NOT ELIGIBLE → HUMAN REVIEW → SELECTION → IMPLEMENTATION GATE`

Arena PASS never means selected, implemented, verified, authorized, safe, or sovereign.

## Implementation firewall
No repository mutation, identity-provider redesign, credentials/tokens, database/API changes, crypto/biometric selection, UI authority, PassSpec/PatchApproval/K15/K3 modification, or alternate mutation path belongs in this frame.
