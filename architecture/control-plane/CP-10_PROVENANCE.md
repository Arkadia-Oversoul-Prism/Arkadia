# CP-10 — AUTHORITY PROVENANCE

**Status:** schema-only / normative / technology-neutral
**Scope:** provenance semantics only. No mechanism selected, no implementation, no enforcement, no repository mutation.

## Constitutional question
Can Arkadia introduce evidence of human-origin authority without allowing the evidence mechanism, PassSpec, PatchApproval, K15, or K3 to become the source of sovereignty?

## Core separation
`EVIDENCE → PROVENANCE → AUTHORIZATION → EXECUTION`

These are distinct states. Evidence does not become authority merely by existing. Provenance does not authorize by itself. Authorization does not execute.

## R3 semantic vector
`SUBJECT → AUTHORITY CLASS → SPECIFIC AUTHORITY EVENT → EVENT ORIGIN → DELIBERATE ORIGIN → EXACT SCOPE → EVENT TIME → DELEGATION LINEAGE → EXPIRY/REVOCATION → NON-SUBSTITUTABLE PROVENANCE → INSPECTABLE PROVENANCE STATE`

All applicable criteria are `PASS / FAIL / UNKNOWN / N/A`. UNKNOWN never silently becomes PASS. R3 requires every mandatory criterion to PASS. There is no partial R3.

## Evidence families
A. Cryptographic  
B. Session-bound  
C. Interaction-bound  
D. Witnessed  
E. Structural  
F. Hybrid

No family receives automatic authority status. A hybrid is only a composition of evidence classes, not authority by name.

## Constitutional prohibitions
- evidence ≠ authority
- identity ≠ authorization
- session ≠ event origin
- interaction ≠ sovereignty
- witness ≠ sovereignty
- structural integrity ≠ human provenance
- aggregation ≠ provenance
- provenance ≠ authorization
- authorization ≠ execution
- publication ≠ mutation
- no parallel identity or authority system
- no alternate mutation path
- human sovereignty remains external

## Selection boundary
Passing criteria establishes candidate eligibility against those criteria only. Eligibility is not selection, implementation, verification, authorization, or safety.
