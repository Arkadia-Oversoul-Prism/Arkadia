# CP-10.2 — MECHANISM ACCEPTANCE CRITERIA

**Status:** schema-only / read-only / normative / technology-neutral

## Principle
A passing criterion establishes candidate eligibility against that criterion. It does not establish authority, correctness, safety, selection, or authorization.

## Evaluation semantics
Every applicable criterion is `PASS / FAIL / UNKNOWN / N/A`.

- PASS: continue evaluation
- FAIL: stop
- UNKNOWN: stop
- UNKNOWN never silently becomes PASS

Eligibility is independent by risk class R0/R1/R2/R3. There is no partial R3.

## R3 protected mutation
R3 requires a complete semantic vector:

`SUBJECT → AUTHORITY CLASS → SPECIFIC AUTHORITY EVENT → EVENT ORIGIN → DELIBERATE ORIGIN → EXACT SCOPE → EVENT TIME → DELEGATION LINEAGE → EXPIRY/REVOCATION → NON-SUBSTITUTABLE PROVENANCE → INSPECTABLE PROVENANCE STATE`

All mandatory criteria must PASS.

## Tier I constitutional constraints
Evidence is not authority. Identity, session, interaction, witness, structural integrity and aggregation cannot silently become provenance or sovereignty. There is no parallel identity/authority system and no alternate mutation path. Human sovereignty remains external.

## Forbidden semantic patterns
`identity→authority`, `session→event origin`, `interaction→sovereignty`, `witness→authority`, `hash→human origin`, `signature→authority`, `approved=true→PROVEN`, `structural validity→human origin`, `PROVEN→authorized`, `authorization→execution`.

## Composition rule
The system is evaluated as one composition. A component passing a criterion does not guarantee that the composed system passes it.

## Implementation boundary
CP-10.2 selects no cryptographic algorithm, credential, auth protocol, UI, database schema, API, identity-provider change, delegation store, revocation infrastructure, or K15/K3 modification.

## Result
CP-10.2 converted the provenance problem into a falsifiable acceptance gate and established the R3 evidence burden used by all later candidate evaluations.
