## 2026-11-18 — Aggregate-PR classification repair (lane-state)

This section is appended. The historical CI evidence above is preserved unchanged and is **not** a test of this repair commit. The previously tested combined candidate `6dcdf0388c157b2b60f6530216167645b958988d` (tree `23b1a9091bf5d42227b162448d977ce819a18547`) remains a separate, earlier measurement.

### Root cause

`scripts/lane_state_refresh.py` assigned PRs to lanes by **exclusive path ownership** only. PR #668 (this integration baseline) composes #663–#667, so its diff touches paths owned by all four lanes. Path ownership therefore placed it in all four, and because its `updated_at` was the newest of any open PR, `_active_thread()` selected it as `active_pr` in all four — superseding the genuine lane PRs #665/#666/#667/#664.

Measured on live data at integration head `0fdf4ca8197b7021cb5d4bc0d36de73ff37fd70c`, running the unmodified classifier against real GitHub payloads:

```
#668  lanes=['1','2','3','4']  updated_at=2026-11-18T13:58:58Z
lane 1: active_pr=668  open=[665, 668]
lane 2: active_pr=668  open=[666, 668]
lane 3: active_pr=668  open=[667, 668]
lane 4: active_pr=668  open=[664, 668]
```

An aggregate evidence PR is not the working owner of the lanes it composes.

### Classification design and rationale

A PR is now classified into exactly one of three kinds:

| Kind | Rule | Recorded in |
|---|---|---|
| **AGGREGATE** | declared in `docs/control-plane/parallel-ui/aggregate-prs.json` | `aggregate_prs` (explicit, auditable) — excluded from every lane's `open_prs` and from `active_pr` selection |
| **LANE** | not declared aggregate, matches ≥1 lane's owned paths | each matching lane's `open_prs` (genuine multi-lane PRs still appear in every lane they touch) |
| **UNASSIGNED** | not declared aggregate, matches no lane | `unassigned_open_prs` |

Deliberately **not** used: a title substring (`integration:`) or a branch prefix (`integration/`). Either would classify a genuine multi-lane implementation PR as aggregate and silently strip it from lane ownership. The declaration is explicit, version-controlled data, so every classification decision is reviewable in the same diff as the code that reads it. No PR number is hardcoded in classifier logic.

Aggregate PRs are **not dropped**: each entry keeps `lanes_touched`, `reason`, `branch` and `head_sha`, so the fact that the diff spans four lanes stays visible to a reviewer.

### Metadata contract and failure behaviour

| Condition | Behaviour |
|---|---|
| Config file absent | No PR is aggregate; classification falls back to path ownership (pre-repair behaviour). Snapshot records `aggregate_config.status = "absent"` so the omission is visible, not assumed. |
| Config unreadable / malformed | Refresh **aborts, exit 2**. It does not fall back to "nothing is aggregate", because that fallback would silently re-admit an aggregate PR as a lane owner — the exact defect being repaired. |
| Declared number not open | Recorded in `aggregate_prs` with `state: "not_open"`, so a stale declaration is visible rather than silently inert. |
| Declared number also a genuine lane PR | Declaration wins; the overlap is recorded under `aggregate_prs` for review. |

### Verification gates — both FAILED, for two distinct and genuine reasons

**Offline: `python3 scripts/lane_state.py --check` → exit 1**

```

DRIFT lane 4 (AGENT-04-ARKANA-WEAVER-LAB.md): declares no active thread, but the snapshot lists open lane PRs [664]
```

This is a **real finding the refresh exposed, not a defect in the repair.** The previous snapshot was observed `2026-11-16T18:18:03Z`; #664–#667 were all created 2026-11-17 and #668 on 2026-11-18, so the snapshot predated every one of them and recorded all four lanes as `idle`. The four lane docs accordingly declare `**Active thread:** none`. A truthful refresh shows those lanes are not idle. The docs are now stale.

**This was not repaired by editing the lane docs.** Rewriting four lane instruction documents to point at PRs, purely to make a guard pass, is exactly the "change lane instruction documents merely to silence a failing guard" that this assignment forbids — and each doc is lane-owned, so a single integration pulse should not re-point all four. The finding is reported for human direction.

**Live: `python3 scripts/lane_state.py --check --verify-live` → exit 1**

```
DRIFT live PR state unavailable (no GitHub token in GH_TOKEN/GITHUB_TOKEN/GITHUB_PERSONAL_ACCESS_TOKEN);
      every claimed-open lane PR is UNKNOWN, not a pass -- re-measure with GitHub read access
```

The live gate is **BLOCKED, not passed**. The guard fails closed by design when it cannot reach GitHub, and this environment has no token. The live gate must be re-run in an environment with `GH_TOKEN` (the CI workflow supplies `${{ github.token }}`).
