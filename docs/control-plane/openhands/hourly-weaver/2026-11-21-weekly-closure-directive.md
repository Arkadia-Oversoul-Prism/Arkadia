### Portfolio scheduler policy

- Maintain one durable portfolio cursor/ledger in this directive's repository-native evidence area, with one row per repository: current default/base SHA, active trajectory/phase, active issue/PR, last pulse, blockers, next legal task, and CI/device evidence.
- Every hourly wake refreshes all three repository states (default branch SHA, open PRs, open issues, CI, latest pulse ledger). The scheduler may inspect all three but executes **at most one bounded task total per pulse**.
- Use deterministic fairness: select the repository with the oldest verified `last_progress_at` among repositories that have a legal, unblocked task; break ties in this fixed order: Sonata → FSN → Arkadia. A repository blocked by missing permission, CI infrastructure, physical device, or human decision is recorded as BLOCKED and does not consume every future slot; rotate to the next legal repository. Recompute from evidence each hour—do not rely on session memory.
- Within the selected repository, continue its existing owned branch/PR first. If none exists, select the first incomplete task in its canonical trajectory/issue/phase ledger. Do not create parallel PRs for the same task, multiply PRs to create activity, or jump to unrelated work.
- One pulse = one bounded change, one test/evidence pass, one durable report, and STOP at review. A PR may be updated repeatedly across pulses. Open a new **draft** PR only when there is no existing PR for that task and a coherent reviewable slice exists.
- Keep at most one active implementation PR per repository task/phase; do not accumulate open PRs merely because hourly cycles are available. Reconcile stale/duplicate PRs before opening another.
- The hourly cadence is a wake-up, not permission to bypass issue scope, branch protections, required checks, or human review. No merge, auto-merge, release, deploy, production activation, credential/secrets change, or external action.
