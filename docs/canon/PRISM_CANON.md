# Arkadia Oversoul Prism Canon

## Canonical identity

**Arkadia Oversoul Prism** is the canonical identity of this repository and the architecture it contains.

> **One human-governed intelligence architecture. Many expressions. One coherent substrate.**

The Prism is the architecture through which human intent, identity, context, knowledge, reasoning, authorization, execution, evidence, verification, and experience are expressed across specialized surfaces without fragmenting authority, provenance, or continuity.

The Prism is **not another product inside Arkadia**. It is the architectural whole that makes Arkadia one system.

## Core model

```
Human intent / authority
        ↓
      Identity
        ↓
      Context
        ↓
     Reasoning
        ↓
   Authorization
        ↓
     Execution
        ↓
      Evidence
        ↓
     Knowledge
        ↓
    Verification
        ↓
     Projection
```

The system may contain many agents, models, tools, interfaces, projects, and providers. They are expressions or mechanisms within the Prism. They do not acquire independent authority merely by existing.

### Governing boundaries

- **Intent ≠ authorization**
- **Authorization ≠ execution**
- **Execution ≠ completion**
- **Completion ≠ approval**
- **Approval ≠ merge**
- **Merge ≠ deployment**
- **Deployment ≠ production acceptance**
- **Evidence ≠ verification**
- **Capability ≠ authority**
- **Interface ≠ substrate**
- **Model/provider ≠ canonical identity**

Where evidence stops, the claim stops. Unknown state must remain explicitly unknown.

## Copy and brand grammar

Preferred first description:

> **[Surface] is a [role] of the Arkadia Oversoul Prism.**

Preferred short brand line:

> **Arkadia Oversoul Prism · [surface role]**

Avoid language that makes a surface appear to be a separate intelligence system, independent memory system, sovereign authority, or replacement for the canonical substrate.

### Human sovereignty

Human authority remains the decision boundary. AI systems may reason, transform, propose, retrieve, execute within granted bounds, and record evidence. They do not become the source of human authority.

## README coherence test

Every README in this repository must make these seven things legible:

1. **Identity** — how the component belongs to the Prism.
2. **Topology** — where it sits in the architecture.
3. **Substrate** — what canonical infrastructure it reuses.
4. **Authority** — what it may and may not decide or execute.
5. **Continuity** — how it participates in shared context/knowledge.
6. **Evidence** — what is implemented, tested, deployed, verified, proposed, or unknown.
7. **Language** — whether its terminology agrees with this canon.

A README fails the coherence test if a reader can reasonably conclude that the component is a separate Arkadia intelligence, authority path, memory system, or incompatible source of truth.

## Relationship to implementation

This document defines identity and language. It does not claim implementation merely because the architecture is specified.

Implementation status must continue to be established by repository evidence, tests, deployment state, and production verification.

**The Prism preserves coherence. Evidence determines what can be claimed.**
